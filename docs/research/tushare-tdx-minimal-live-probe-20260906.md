# Tushare TDX 最小只读探针合同

> 核验日期：2026-09-06（Asia/Shanghai）
>
> 范围：`tdx_index`、`tdx_daily`、`tdx_member` 的公开官方文档事实、最小只读探针合同，以及 2026-09-06 的脱敏执行结果。
>
> 边界：本文不含 Token、账号、SecretRef、原始响应正文或其他凭证信息；官方文档核验未读取凭证，真实探针仅由容器内 `CredentialStore` 懒加载凭证。

## 1. 官方接口事实

三个接口的官方页面均声明：用户积累 **6000 积分**可调取。积分门槛是文档条件，不证明任何具体账号已获得接口访问权。

### 1.1 `tdx_index`

- 官方文档：<https://tushare.pro/document/2?doc_id=376>
- 用途：获取通达信板块基础信息，包括概念、行业、风格、地域等板块。
- 单次上限：**1000 行**；官方说明可按日期循环提取。

输入参数：

| 字段 | 类型 | 必选 | 含义 |
|---|---|---:|---|
| `ts_code` | `str` | 否 | 板块代码，格式 `xxxxxx.TDX` |
| `trade_date` | `str` | 否 | 交易日期，格式 `YYYYMMDD` |
| `idx_type` | `str` | 否 | 概念板块、行业板块、风格板块或地区板块 |

输出字段：

`ts_code`, `trade_date`, `name`, `idx_type`, `idx_count`, `total_share`, `float_share`, `total_mv`, `float_mv`。

日期与完整度限制：

- 输入和输出均有显式 `trade_date`，但接口没有 `start_date` / `end_date` 参数。
- 官方未声明历史起始日期、分页游标、总记录数或分类修订规则。
- 返回少于 1000 行不能单独证明全量；返回恰好 1000 行时应视为可能截断并停止准入判断。

### 1.2 `tdx_daily`

- 官方文档：<https://tushare.pro/document/2?doc_id=378>
- 用途：获取通达信板块行情、成交与估值数据。
- 单次上限：**3000 行**；官方说明可按板块代码和日期循环提取。

输入参数：

| 字段 | 类型 | 必选 | 含义 |
|---|---|---:|---|
| `ts_code` | `str` | 否 | 板块代码，格式 `xxxxxx.TDX` |
| `trade_date` | `str` | 否 | 单一交易日期，格式 `YYYYMMDD` |
| `start_date` | `str` | 否 | 开始日期 |
| `end_date` | `str` | 否 | 结束日期 |

输出字段：

`ts_code`, `trade_date`, `close`, `open`, `high`, `low`, `pre_close`, `change`, `pct_change`, `vol`, `amount`, `rise`, `vol_ratio`, `turnover_rate`, `swing`, `up_num`, `down_num`, `limit_up_num`, `limit_down_num`, `lu_days`, `3day`, `5day`, `10day`, `20day`, `60day`, `mtd`, `ytd`, `1year`, `pe`, `pb`, `float_mv`, `ab_total_mv`, `float_share`, `total_share`, `bm_buy_net`, `bm_buy_ratio`, `bm_net`, `bm_ratio`。

其中官方注明 `amount` 为成交额，单位**万元**；对期货指数该字段存储持仓量。

日期与完整度限制：

- 支持单日和日期区间查询，输出含显式 `trade_date`。
- 官方未声明历史起始日期、分页游标、总记录数或完整性承诺。
- 返回恰好 3000 行时应视为可能截断；业务使用前还必须证明目标日期的每个入选板块均存在唯一行情记录。

### 1.3 `tdx_member`

- 官方文档：<https://tushare.pro/document/2?doc_id=377>
- 用途：获取通达信各板块成分股信息。
- 单次上限：**3000 行**；官方说明可按日期和板块代码循环提取。

输入参数：

| 字段 | 类型 | 必选 | 含义 |
|---|---|---:|---|
| `ts_code` | `str` | 否 | 板块代码，格式 `xxxxxx.TDX` |
| `con_code` | `str` | 否 | 成分股票代码 |
| `trade_date` | `str` | 否 | 单一交易日期，格式 `YYYYMMDD` |
| `start_date` | `str` | 否 | 开始日期 |
| `end_date` | `str` | 否 | 结束日期 |

输出字段：

`ts_code`, `trade_date`, `con_code`, `con_name`。

日期与完整度限制：

- 支持单日和日期区间查询，输出含显式 `trade_date`。
- 官方未声明历史起始日期、分页游标、总记录数或分类修订规则。
- `tdx_index.idx_count` 可作为成员数量对账基准，但只有实际验证逐板块唯一 `con_code` 数量与 `idx_count` 相等，才能证明该次响应完整。
- 返回恰好 3000 行时应视为可能截断并停止准入判断。

## 2. 最小只读探针合同

### 2.1 前置条件

1. 仅在受保护凭证已由系统管理员配置、且用户授权只读权限探针后执行；目标接口访问权是探针结论，不作为循环前置条件。
2. 选择一个已经收盘且确认是交易日的固定日期 `D`；探针期间不得改用当前日期或隐式默认日期。
3. 凭证必须由既有受保护运行时注入；不得出现在命令参数、环境打印、日志、异常正文或证据文件中。
4. 只调用查询接口，不写业务数据库、不发布 Definition、不生成 Candidate、不激活策略。

### 2.2 权限预检

先以固定日期 `D` 调用 `tdx_index` 和 `tdx_daily`。任一接口返回非成功业务码即停止，不调用成员接口；只有两者均成功，才进入下列覆盖探针。

### 2.3 最小覆盖调用序列

| 步骤 | 调用 | 最小参数 | 通过条件 |
|---:|---|---|---|
| 1 | `tdx_index` | `trade_date=D, idx_type=行业板块` | 业务成功；1–999 行；所有行日期为 `D`、类型为行业板块；`ts_code` 唯一；`name` 非空；`idx_count >= 0` |
| 2 | `tdx_index` | `trade_date=D, idx_type=概念板块` | 业务成功；1–999 行；所有行日期为 `D`、类型为概念板块；其余规则同上 |
| 3 | `tdx_daily` | 分别对步骤 1、2 中按 `ts_code` 升序选出的首个板块调用 `ts_code=<code>, trade_date=D` | 每个板块恰好一条目标日记录；`pct_change` 和 `amount` 可解析；股票板块 `amount >= 0` |
| 4 | `tdx_member` | 对同两个板块分别调用 `ts_code=<code>, trade_date=D` | 全部行 `ts_code`、`trade_date` 与请求一致；`con_code` 唯一且带可识别市场后缀；`con_name` 非空；行数等于对应 `idx_count` 且少于 3000 |
| 5 | 重复步骤 1–4 | 参数完全相同 | 规范化后的行数、关键字段集合及 SHA-256 与第一次一致 |

这里“规范化”仅允许：按稳定主键排序、统一空值表示、采用固定字段顺序和 UTF-8 编码；不得删除记录、猜测分类、补写日期或改写来源值。

### 2.4 最小证据输出

探针只应保存脱敏元数据，不保存凭证或完整原始数据：

- 调用时间、固定交易日 `D`、接口名和非敏感请求参数；
- HTTP 状态、Tushare 业务码、耗时和返回行数；
- 每次规范化响应的 SHA-256；
- 每个样本板块的 `ts_code`、`idx_type`、`idx_count`、行情行数和成员行数；
- 单位校验、日期一致性、唯一性和计数对账结果；
- 失败时的稳定错误分类，不保存可能包含账号信息的原始异常正文。

### 2.5 Fail-closed 条件

出现以下任一情况即停止，不扩大调用范围，也不得给出准入结论：

- 无权限、限流、服务错误或非成功业务码；
- 日期缺失或与 `D` 不一致；
- 行数达到接口单次上限；
- 板块代码、成分代码重复或缺失；
- `tdx_index.idx_count` 与唯一成员数不一致；
- 同参数重复调用的规范化结果不一致；
- 接口单位、历史边界、许可或自动化留存边界仍无法确认。

结论：凭证和网络均已进入 Tushare 业务鉴权层，但当前账号不能访问 TDX 板块组。该结果只阻断 Tushare Provider 的板块 Dataset 绑定，不代表 WorkBuddy Connector 固定配方不可执行；Tushare Provider 代码开发仍不得启动。

## 4. 本文结论边界

公开文档只能确认接口合同、6000 积分门槛和页面声明的单次限量。真实探针进一步确认当前账号被 `40203` 阻断，但不能证明返回全量、分类历史稳定、重复调用确定，或自动化留存已获许可。本文只评价 Tushare TDX 这一 Source 与目标 Dataset 的绑定状态，不评价 TDX Connector、WeStock MCP、MX-DS MCP 或其固定组合的总体覆盖。
