## 四、根因分析（Phase 0 必做项）

### 4.1 9 个 SKIP 工具的根因（v1 方案找错了方向）

**v1 假设**：`save_snapshot` 异常被吞 → DB 写入失败
**实际**：MCP 返回数据但**代码用错误的 key 去查结果**

**证据 1：100% 命中"data_type ≠ tool_name"规则**

| 状态 | data_type | tool_name | 一致? |
|------|-----------|-----------|-------|
| ✅ 8 OK | market_overview, limit_stats, hot_sectors, limit_up_ladder, broken_limit_up, cls_news, concept_ranking, sector_analysis | （与 data_type 相同）| ✅ |
| ❌ 9 SKIP | market_replay | market_replay_workflow | ❌ |
| ❌ 9 SKIP | market_leaders | market_leaders_pick | ❌ |
| ❌ 9 SKIP | board_break | board_break_analysis | ❌ |
| ❌ 9 SKIP | capital_flow_mkt | capital_flow | ❌ |
| ❌ 9 SKIP | auction_scan | auction_market_scan | ❌ |
| ❌ 9 SKIP | auction_wts | auction_weak_to_strong | ❌ |
| ❌ 9 SKIP | auction_feedback | auction_limitup_feedback | ❌ |
| ❌ 9 SKIP | stock_rank_volume | stock_rank | ❌ |
| ❌ 9 SKIP | stock_rank_turnover | stock_rank | ❌ |

**证据 2：`mcp_client.call_batch` 用 tool_name 作 key 返回**

```python
# mcp_client.py line 222-227
async def call_batch(self, tools: List[Dict[str, Any]]) -> Dict[str, Any]:
    results = {}
    for tool_spec in tools:
        name = tool_spec["name"]          # ← tool_name
        ...
        results[name] = result            # ← key 是 tool_name
    return results
```

**证据 3：`market_data_collector.py` 用 data_type 查，命中为空**

```python
# market_data_collector.py line 153 (run() 内)
for tool in group:
    data_type = tool["data_type"]
    tool_name = tool["name"]
    raw_data = results.get(data_type, {})  # ← BUG：data_type 而不是 tool_name
    if not raw_data:
        logger.warning(f"  [SKIP] {data_type} 无数据")  # ← 永远命中这行
        ...
```

### 4.2 修复方案

**单行修改：**

```python
# market_data_collector.py line 153
- raw_data = results.get(data_type, {})
+ raw_data = results.get(tool_name, {})
```

**配套改动**（强烈建议，但非阻塞）：

```python
# line 156 SKIP 日志加上 tool_name 便于诊断
- logger.warning(f"  [SKIP] {data_type} 无数据")
+ logger.warning(f"  [SKIP] {data_type} (tool={tool_name}) 无数据，results keys={list(results.keys())[:5]}")
```
