# invest-infra ETF 数据覆盖与 Provider 韧性实施计划 v1.0

> 治理状态：`ACTIVE`
> 制定日期：2026-09-02
> 修订日期：2026-09-02（压缩为三阶段最小闭环）
> 优先级：`P0`
> 计划定位：先用真实证据判断备用数据源价值，再做最小接入
> 授权边界：现有安全基线已完成；真实网络探针、代码实施、历史回填/部署分别独立授权

## 1. 背景与决策

当前系统已有 Provider Contract、请求/尝试/批次证据、日行情 revision、
Input Snapshot、CandidatePool 状态机和 StrategyVersion 治理。当前实际阻塞是 ETF
行情仍依赖不稳定的东方财富链路，而不是缺少一套新的数据平台：

- AkShare 已有有界瞬时错误重试，但真实请求仍持续出现 `RemoteDisconnected`；
- AkShare 与 Efinance 可能共享东方财富上游，不能视为独立冗余；
- CifangQuant 历史接口缺少 `amount`，不能单独满足现有策略输入；
- BaoStock 可能提供独立的 OHLCV/amount，但尚未验证目标 ETF 覆盖、未复权口径和单位。

因此后续只做三件事：真实探针、准入决策、最小接入。探针不通过即停止，不提前建设
字段级路由、覆盖平台或通用 Provider 编排。

## 2. 已完成基线（不计入后续阶段）

- AkShare 仅对明确的瞬时传输错误做 3 次有界重试，退避 `1s / 2s`；
- 参数、数据格式、字段和单位错误不重试；
- CandidatePool 已引入 `market_data_fingerprint`，覆盖 Domain、Storage、Pipeline 和迁移；
- 数据或证据不完整时仍 fail closed，不发布快照和候选池；
- 相关测试、Ruff、架构检查和差异检查已通过。

上述改动只建立安全基线，不证明真实数据覆盖已经改善。

## 3. 目标与成功标准

最小目标：判断 BaoStock 能否作为当前 16 只 active ETF 日行情的独立备用源；若能，
按现有 Provider 契约实现一个最小 Adapter，并证明断线降级不会破坏数据口径、证据链和幂等性。

成功必须同时满足：

1. 16 只 ETF 在有效生命周期内具备可解释的日线覆盖；
2. 使用未复权口径，OHLCV/amount 字段、单位和数量级经过真实验证；
3. 备用源只在明确的瞬时传输错误下启用；
4. 字段缺失、单位异常、日期不足或证据不完整继续阻断发布；
5. 相同业务输入重试产生相同数据指纹和业务结果。

## 4. 范围边界

纳入：

- 16 只 active ETF 的 BaoStock 只读真实探针；
- 近期窗口和至少一个历史窗口的 OHLCV/amount 覆盖与跨源对照；
- `admit / research_only / reject` 准入结论；
- 仅在 `admit` 后实现最小 BaoStock Adapter、错误降级和验收测试。

不纳入：

- 持久化覆盖矩阵平台、Provider 评分、动态可靠性或通用编排引擎；
- 在探针前设计字段级多源拼接和路由；
- ETF Profile、指数成分、估值、新闻等研究数据扩展；
- Web Run Flow、告警、交易信号、LLM 排名和策略规则调整；
- 全量历史回填、部署、发布和生产切换。

## 5. 三阶段实施

### 阶段 1：只读真实探针

**目的：** 用一次性、可复算的探针报告回答 BaoStock 是否值得接入。

探针范围：

- 标的：当前 16 只 active ETF，分母按上市生命周期计算；
- 窗口：近期窗口 + 至少一个历史窗口；只有异常时再扩大窗口定位；
- 字段：date、open、high、low、close、volume、amount；
- 口径：`adjustflag="3"`，验证未复权；
- 检查：覆盖率、缺失、重复、乱序、单位、数量级、耗时、空结果和错误类型；
- 对照：与现有可用数据做 close、volume、amount 抽样交叉校验。

产物仅为一份归档报告，不建设数据库、服务或长期运行平台。报告不得包含凭证、代理地址和
宿主机敏感路径。

**退出条件：** 16 只 ETF 探针完成，事实和未知项清晰；失败不得记为成功或合法空结果。

### 阶段 2：准入决策与最小合同冻结

**目的：** 根据阶段 1 证据决定是否编码，不预设必须接入。

准入结论三选一：

- `admit`：覆盖、未复权口径、amount 单位及独立性均可接受；
- `research_only`：可用于人工研究，但不满足正式候选池输入要求；
- `reject`：关键口径或覆盖无法证明。

仅在 `admit` 时冻结实现所需的最小合同：symbol 映射、日期语义、字段单位、空结果语义、
可重试错误和证据字段。若单一 BaoStock 响应可完整提供 OHLCV/amount，则不引入字段级拼接。

**停止条件：** 结论为 `research_only` 或 `reject` 时归档结果并关闭本轮接入，不用扩大架构
或放松质量门槛绕过。

### 阶段 3：最小 Adapter 与验收

**目的：** 只实现阶段 2 已证明必要的备用能力。

实施与验收：

- Adapter 转换外部协议为现有领域对象，复用现有 ProviderRequest/Attempt/Batch；
- 不修改 CandidatePool 评分、策略参数和发布状态机；
- 仅明确的瞬时传输错误允许尝试 BaoStock；
- 字段缺失、单位异常、日期不足、契约错误和持续断连必须明确失败；
- 完成 Adapter 单元/契约测试、16 只 ETF 真实抽样对账、断线降级和幂等验证；
- 失败运行不得创建可发布快照或 CandidatePool。

阶段 3 通过只代表备用链路具备接入条件，不自动授权历史回填、部署或生产切换。

## 6. 授权门禁

只保留三个授权边界：

| 授权 | 范围 | 明确不包含 |
|---|---|---|
| 探针授权 | 阶段 1 的真实网络只读请求和报告归档 | 代码接入、数据库写入 |
| 代码实施授权 | `admit` 后的阶段 3 最小 Adapter 与测试 | 回填、部署、生产切换 |
| 运行变更授权 | 历史回填、部署或生产切换的具体批次 | 未列明的其他数据源和业务功能 |

阶段 2 是基于探针事实形成决策和最小合同，不单独增加形式化 Gate。

## 7. 风险控制

| 风险 | 控制方式 |
|---|---|
| BaoStock 覆盖或单位不合格 | 编码前探针；不合格即停止 |
| 多个 SDK 实际共享上游 | 记录实际端点和失败相关性，不按 SDK 数量计算冗余 |
| 备用源数据污染正式结果 | 复用现有证据、质量门禁和数据指纹，失败关闭 |
| 方案再次平台化膨胀 | 一次性报告、单一 Adapter；第三个真实用例出现前不抽象通用平台 |
| 历史回填放大错误 | 独立授权，且必须在 Adapter 验收后进行 |

## 8. 完成定义

出现以下任一结果即可关闭本计划：

1. BaoStock 被 `admit`，最小 Adapter 通过合同、真实链路、故障和幂等验收；或
2. BaoStock 被 `research_only/reject`，结论有真实探针证据支持，并明确系统仍无合格备用源。

无论哪种结果，都不得以默认值、静默降级、共享上游伪装或放松数据质量门槛宣称覆盖成功。
历史回填、部署和生产切换始终保持独立授权。
