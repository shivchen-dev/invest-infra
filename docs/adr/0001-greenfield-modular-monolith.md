# ADR-0001：采用 Greenfield 模块化单体

- 状态：Accepted
- 日期：2026-07-30

## 决策

新版本从空仓库开始，以 Python 模块化单体为核心，API 与数据流水线作为独立进程和独立依赖项目部署。前端使用 TypeScript。首期不使用微服务。

## 原因

旧版技术债主要来自边界缺失、任务脚本化、重复模型和依赖混装，而不是 Python 语言本身。直接采用多语言微服务会把代码问题转换为分布式系统问题。

## 后果

- 可以复用 Python 数据生态；
- API 镜像不包含计算依赖；
- 模块未来可独立拆出；
- 需要通过 CI 强制依赖方向。
