## 设计问题与约束

### 1. MCP 工具频率限制
- **问题:** 批量调用 wudao_aStock MCP 工具可能触发频率限制
- **解决方案:** 
  - 添加 100ms 间隔
  - 实现失败重试（最多 3 次）
  - 指数退避策略

### 2. QQ 消息长度限制
- **问题:** QQ 消息单条长度有限，长报告需拆分
- **解决方案:**
  - 设置每条消息最大 4000 字符
  - 超长内容分多条发送
  - 关键信息优先展示

### 3. A股交易时间约束
- **问题:** 非交易时间（周末/节假日）不应推送
- **解决方案:**
  - cron 表达式限定 `1-5`（周一至周五）
  - 脚本内增加交易日校验
  - 节假日配置表（可选）

### 4. 数据延迟
- **问题:** 盘中数据可能有 15 分钟延迟
- **解决方案:**
  - 盘后报使用收盘数据（延迟小）
  - 盘中轮询注明"数据截至 XX:XX"
  - 不依赖实时行情

## v2.0 新增发现

### 5. 统一出口需求（核心变更）
- **发现:** 用户需要单一报告出口，不是两套独立系统
- **影响:** 架构从「方案A完全独立」升级为「统一报告引擎作为终态」
- **解决:** 三阶段演化路径

### 6. 数据融合冲突仲裁
- **问题:** 两个数据源（PG vs MCP）可能数据冲突
- **影响:** 需要明确的仲裁规则，否则报告内容不确定
- **解决:** 数值数据用 MCP 实时数据，AI总结用 Morning Briefing

### 7. Morning Briefing 适配层必要性
- **问题:** Morning Briefing 的盘前洞察需要注入新模块
- **影响:** 需要新增 morning_briefing_adapter.py
- **解决:** 阶段2 重点任务
