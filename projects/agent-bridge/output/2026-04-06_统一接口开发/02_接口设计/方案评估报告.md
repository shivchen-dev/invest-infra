## 3. 优先级调整

### 3.1 调整前
```
P0: Bridge 工厂、同步 API、响应格式
P1: 异步接口、话题管理、统一网关
P2: 模板验证、轮数决策、预注册模板、流式响应、认证
```

### 3.2 调整后
```
P0 (1-2天):
├── Bridge 工厂
├── DeepSeek 同步 API
├── 基础模板验证 (格式检查)
└── 统一响应格式

P1 (2-3天):
├── 异步任务队列
├── 三层验证中间件 (完整)
├── 三级轮数决策
├── 对话结束判断
├── 预注册模板机制
└── 话题管理端点

P2 (可选):
├── 流式响应 (SSE)
├── 优先级队列
└── 监控面板

P3/删除:
└── 认证机制 (本地服务暂不需要)
```

### 3.3 调整原因

| 调整项 | 原优先级 | 新优先级 | 原因 |
|--------|---------|---------|------|
| 模板验证 | P2 | P0 | 核心差异点，决定咨询质量 |
| 预注册模板 | P2 | P1 | 比 SDK 方案更灵活 |
| 异步接口 | 未明确 | P1 | 复杂查询必需，但非阻塞 |
| 流式响应 | P2 | P3 | 当前场景非必需 |
| 认证机制 | P2 | 删除 | 本地服务暂不需要 |

---

## 4. 关键决策

### 决策 1: 专注 DeepSeek，延后 Copilot
- **决策**: Phase 3 先实现 DeepSeek API，Copilot 延后
- **理由**: Copilot 当前不稳定（二次验证问题）
- **影响**: 减少初期工作量，提高成功率

### 决策 2: 模板验证强制化
- **决策**: P0 基础验证 + P1 三层验证
- **理由**: 规范化咨询是核心差异点
- **影响**: 提升咨询质量，增加开发工作量

### 决策 3: 异步接口移至 P1
- **决策**: 异步从 P0 移至 P1
- **理由**: 同步可先验证核心流程
- **影响**: 复杂查询可能超时，需要重试机制

### 决策 4: 删除认证机制
- **决策**: 认证从 P2 移至 P3/删除
- **理由**: 本地服务，单用户场景
- **影响**: 无安全隔离，但简化部署
